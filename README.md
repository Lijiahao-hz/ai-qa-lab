# ai-qa-lab

一个测试练手仓库。目标不是"写个 demo"，是把 **测什么 → 怎么判 → 怎么证明** 这个闭环跑通一遍。

## 这是什么

用 pytest 为一个小型模块（`calc.py`）编写测试，覆盖三类场景：**正常路径、异常路径、边界值**。

## 目录结构

```
calc.py               被测对象：4 个函数（加、减、除、密码校验）
tests/test_calc.py    8 条测试用例
```

## 怎么跑

```bash
python3 -m pip install pytest
python3 -m pytest -v
```

预期输出：`8 passed`

## 用例设计

| 被测函数 | 用例数 | 覆盖场景 |
|---|---|---|
| `add` | 2 | 正数相加、正负数相加 |
| `subtract` | 1 | 常规减法 |
| `divide` | 2 | 正常除法、除数为 0 时抛异常 |
| `is_valid_password` | 3 | 长度不足、纯数字、合法密码 |

## 三个刻意的选择

**1. 除零用 `pytest.raises` 断言异常，而不是断言返回空值。**
"报错"本身是接口契约的一部分——要测的不是"它挂了"，而是"它按约定挂了"。

**2. 密码校验单独测了 7 位的 `abc1234`。**
规则是"少于 8 位不通过"，最容易出错的从来不是 3 位或 15 位，而是 7 位和 8 位这条线。

**3. 每条用例只验证一个点。**
失败时能立刻定位到具体行为，而不是面对一条"整体不通过"的用例去猜哪里坏了。

## 已知局限

- 只覆盖单函数行为，未涉及模块间的交互
- 没有接口层、UI 层测试
- 未接入 CI，目前依赖手动执行
- 断言只验证结果正确性，未覆盖性能与并发
